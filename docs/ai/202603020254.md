# ComputationGraph の ID ベース比較

## 問題

`ComputationGraph` の `Eq`/`Ord` インスタンスが構造的比較を行っていた。

```purescript
derive instance Eq a => Eq (ComputationGraph a)
derive instance Ord a => Ord (ComputationGraph a)
```

`Set.member`/`Map.lookup` で毎回ツリー全体を比較するため O(n)、全体で O(n²) 以上になっていた。

## 解決策

各ノードにユニーク ID を追加し、ID ベースの比較に変更。

### 変更点

1. `src/ComputationGraph.js` を追加（ID 生成 FFI）
2. 全コンストラクタに ID フィールドを追加
3. `Eq`/`Ord` を ID ベースに手動実装
4. スマートコンストラクタ `mkVal`, `mkAdd` 等を追加
5. `Differentiable` クラスに `toNumber` を追加（値ベース比較用）
6. `GPT.purs` の `softmax` で `maxByValue` を使用
7. `Train.purs` の `extractGrads` で `fromMaybe 0.0` を使用（未使用パラメータ対応）

### コード

```javascript
// src/ComputationGraph.js
let nextId = 0;
export const genId = () => nextId++;
```

```purescript
data ComputationGraph a
  = Val Int a
  | Add Int a (ComputationGraph a) (ComputationGraph a)
  | ...

instance Eq (ComputationGraph a) where
  eq a b = nodeId a == nodeId b

instance Ord (ComputationGraph a) where
  compare a b = compare (nodeId a) (nodeId b)

mkVal :: Number -> ComputationGraph Number
mkVal v = unsafePerformEffect do
  id <- genId
  pure $ Val id v
```

## 検証結果

- ビルド: 成功
- テスト: 成功
- 実行: クラッシュせず動作（以前は `fromJust` で即座に失敗）
- パフォーマンス: 未検証（180秒でタイムアウト、まだ遅い可能性あり）
