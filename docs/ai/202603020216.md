# collectEdges の OOM 修正

## 問題

`Autograd.purs` の `collectEdges` 関数が共有サブグラフを複数回走査していた。

```purescript
Add _ a b ->
  [ { source: expr, target: a, weight: unit }
  , { source: expr, target: b, weight: unit }
  ] <> collectEdges a <> collectEdges b  -- 重複走査
```

ニューラルネットワークでは部分グラフの共有が頻繁に発生するため、これは O(2^depth) の計算量になり、numSteps=1 でも 8GB ヒープで OOM が発生していた。

## 解決策

`collectEdges` を訪問済みノードを `Set` で追跡する形に修正した。

### 変更点

1. `Data.Set` をインポート
2. `collectEdges` の型を変更:
   - 旧: `ComputationGraph Number -> Array Edge`
   - 新: `Set (ComputationGraph Number) -> ComputationGraph Number -> { visited :: Set, edges :: Array Edge }`
3. 訪問済みノードはスキップして空配列を返す
4. `collectUnary` と `collectBinary` ヘルパーで visited セットを伝播

### コード

```purescript
collectEdges :: Set (ComputationGraph Number) -> ComputationGraph Number -> { visited :: Set (ComputationGraph Number), edges :: Array { source :: ComputationGraph Number, target :: ComputationGraph Number, weight :: Unit } }
collectEdges visited expr
  | Set.member expr visited = { visited, edges: [] }
  | otherwise = case expr of
      Val _ -> { visited: Set.insert expr visited, edges: [] }
      Add _ a b -> collectBinary visited expr a b
      Mul _ a b -> collectBinary visited expr a b
      Pow _ a _ -> collectUnary visited expr a
      Exp _ a -> collectUnary visited expr a
      Log _ a -> collectUnary visited expr a
      Relu _ a -> collectUnary visited expr a

collectUnary visited parent child =
  let result = collectEdges (Set.insert parent visited) child
  in { visited: result.visited
     , edges: [ { source: parent, target: child, weight: unit } ] <> result.edges
     }

collectBinary visited parent a b =
  let resultA = collectEdges (Set.insert parent visited) a
      resultB = collectEdges resultA.visited b
  in { visited: resultB.visited
     , edges: [ { source: parent, target: a, weight: unit }
              , { source: parent, target: b, weight: unit }
              ] <> resultA.edges <> resultB.edges
     }
```

## 検証結果

- メモリ使用量: 120-130 MB で安定（以前は指数的に増加）
- OOM は解消された
